# Phase 13 Plan - Wave 3: Monitoring & Resiliency (13-03)

## Goal
Implement auditd liveness monitoring and worker connection resiliency.

<task id="13.3.1" wave="3" autonomous="true" requirements="REQ-LIV-01">
    <read_first>
        - src/sentinel/cmd/sentinel-a/main.go
    </read_first>
    <action>
        Implement `auditd` liveness monitoring in the main daemon.
        1. Periodically check `auditd` service status (via systemd dbus or `auditctl -s`).
        2. Monitor the health of the IPC socket connection.
    </action>
    <acceptance_criteria>
        - Daemon detects when `auditd` is stopped or the worker crashes.
    </acceptance_criteria>
</task>

<task id="13.3.2" wave="3" autonomous="true" requirements="REQ-RES-01">
    <read_first>
        - src/sentinel/cmd/sentinel-a/audit_consume.go
    </read_first>
    <action>
        Implement exponential backoff for the worker's IPC connection.
        1. Wrap the `net.Dial` call in a loop with increasing sleep duration.
        2. Cap the backoff at 5 minutes.
    </action>
    <acceptance_criteria>
        - Worker successfully reconnects if the main daemon is restarted.
        - No tight loops on connection failure.
    </acceptance_criteria>
</task>

<task id="13.3.3" wave="3" autonomous="true" requirements="REQ-TEL-01">
    <read_first>
        - src/sentinel/cmd/sentinel-a/main.go
    </read_first>
    <action>
        Implement liveness alerting for the audit subsystem.
        1. On detection of audit failure, emit an `auditd_failed` event to the Ingestion Service.
        2. On recovery, emit `auditd_recovered`.
    </action>
    <acceptance_criteria>
        - Backend receives alerts when `auditd` state changes on the host.
    </acceptance_criteria>
</task>

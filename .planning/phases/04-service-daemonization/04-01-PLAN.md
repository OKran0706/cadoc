# 04-01: Service Daemonization

## Objective
Wrap the Sentinel binary in a native systemd unit file with crash-recovery capabilities, constrained privileges, and file sandboxing (including auto-provisioning of `/var/lib/canary`).

## Context
- `04-CONTEXT.md` explicitly designates dropping full root capabilities (keeping `CAP_BPF` and network capabilities) and sandboxing the filesystem using `ProtectSystem=strict` and `StateDirectory=canary`.

## Tasks

```xml
<task id="create_systemd_unit">
  <action>
    Create a new systemd unit file definition at `deploy/sentinel.service`. 
    Configure `[Service]` with `Restart=always`, `RestartSec=10`, `CapabilityBoundingSet=CAP_BPF CAP_PERFMON CAP_SYS_RESOURCE CAP_NET_ADMIN`, `AmbientCapabilities=CAP_BPF CAP_PERFMON CAP_SYS_RESOURCE CAP_NET_ADMIN`.
    Add sandboxing attributes: `ProtectSystem=strict`, `StateDirectory=canary`, `PrivateTmp=true`. 
    Set `ExecStart=/opt/canary/sentinel`.
  </action>
  <read_first>
    - .planning/phases/04-service-daemonization/04-CONTEXT.md
    - .planning/research/ARCHITECTURE.md
  </read_first>
  <acceptance_criteria>
    - `deploy/sentinel.service` contains `CapabilityBoundingSet=CAP_BPF`
    - `deploy/sentinel.service` contains `ProtectSystem=strict`
    - `deploy/sentinel.service` contains `StateDirectory=canary`
  </acceptance_criteria>
</task>

<task id="update_deployment_script">
  <action>
    Update `scripts/install-sentinel.sh` (or create it if missing) to copy `deploy/sentinel.service` to `/etc/systemd/system/sentinel.service` and execute `systemctl daemon-reload && systemctl enable --now sentinel.service`.
  </action>
  <read_first>
    - scripts/install-sentinel.sh
  </read_first>
  <acceptance_criteria>
    - `scripts/install-sentinel.sh` contains `cp deploy/sentinel.service /etc/systemd/system/`
    - `scripts/install-sentinel.sh` contains `systemctl daemon-reload`
    - `scripts/install-sentinel.sh` contains `systemctl enable --now sentinel.service`
  </acceptance_criteria>
</task>
```

## Verification
- Run `cat deploy/sentinel.service` and verify all isolation constraints are documented.
- Run `cat scripts/install-sentinel.sh` and ensure the service management commands are present.

## Must Haves
- `ProtectSystem=strict` is present to ensure zero-disk modifications are blocked centrally except for `/var/lib/canary`.

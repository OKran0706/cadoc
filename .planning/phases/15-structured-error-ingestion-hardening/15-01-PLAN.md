# Plan 15-01: Typed Vault Sentinel Errors

## Goal
Add two typed sentinel errors (`ErrForbidden`, `ErrNotFound`) to the `vault` package and wrap them at the HTTP response detection site in `GetSecretField`. This makes callers able to use `errors.Is` instead of brittle string matching.

## Tasks

### Task 1: Add Sentinel Errors and HTTP Status Detection to vault/client.go

<read_first>
- src/sentinel/internal/vault/client.go (full file — understand current error wrapping in GetSecretField and Logical().Read usage)
</read_first>

<action>
Make two targeted changes to `src/sentinel/internal/vault/client.go`:

**Change 1** — Add sentinel error variables after the `import` block:

```go
// Sentinel errors for Vault HTTP response codes.
// Callers should use errors.Is to check for specific conditions.
var (
    // ErrForbidden is returned when Vault responds with HTTP 403 (token expired or insufficient policy).
    ErrForbidden = errors.New("vault: forbidden (403)")
    // ErrNotFound is returned when Vault responds with HTTP 404 (secret path does not exist).
    ErrNotFound = errors.New("vault: not found (404)")
)
```

Add `"errors"` to the import block.

**Change 2** — In `GetSecretField`, inspect the raw Vault API error string to wrap the correct sentinel error. Replace:

```go
secret, err := c.vault.Logical().Read(apiPath)
if err != nil {
    return "", fmt.Errorf("read secret %s (api: %s): %w", path, apiPath, err)
}
```

With:

```go
secret, err := c.vault.Logical().Read(apiPath)
if err != nil {
    errStr := err.Error()
    switch {
    case strings.Contains(errStr, "403"):
        return "", fmt.Errorf("read secret %s: %w", path, ErrForbidden)
    case strings.Contains(errStr, "404"):
        return "", fmt.Errorf("read secret %s: %w", path, ErrNotFound)
    default:
        return "", fmt.Errorf("read secret %s (api: %s): %w", path, apiPath, err)
    }
}
```

Note: The Vault SDK does not expose typed HTTP errors directly — it returns string-formatted errors from the server. We centralize the string inspection here (at the package boundary) so all callers above can use clean `errors.Is` checks. This is the correct pattern for wrapping opaque SDK errors.
</action>

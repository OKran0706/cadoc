<objective>
Fix two critical concurrency bugs discovered in the Phase 18 code review:
- CR-001: Goroutine leak in `handleSentinelConn` — the event-forwarding goroutine has no context cancellation path, leaking on every reconnect cycle.

## Task 1 — Fix CR-001: Add context cancellation to `handleSentinelConn`

**File:** `src/sentinel/cmd/sentinel-a/audit_consume.go`

Current code (lines 68-121):
```go
func handleSentinelConn(conn net.Conn, agg *auditmon.Aggregator) {
    defer conn.Close()
    errChan := make(chan error, 2)
    stopForwarding := make(chan struct{})
    defer close(stopForwarding)
    // goroutine A: forward events — selects on agg.Events() and stopForwarding
    // goroutine B: read SET_MAP commands — sends to errChan on EOF
```

**Problem:** If the writer goroutine (A) fails and sends to `errChan`, `handleSentinelConn` returns, closing `stopForwarding`. But goroutine B (the scanner) is blocked inside `bufio.Scanner.Scan()` and may not notice the connection was closed immediately. Additionally, if both goroutines fail simultaneously, `errChan` (cap 2) fills, but only one error is ever drained. Goroutines are effectively leaked until the OS reclaims the closed socket.

**Fix:** Replace `stopForwarding` channel with a `context.WithCancel`. Pass the derived context to the forwarding goroutine's loop, and close the connection explicitly on cancel to unblock the scanner.

Replace `handleSentinelConn` entirely:

```go
func handleSentinelConn(conn net.Conn, agg *auditmon.Aggregator) {
    defer conn.Close()

    ctx, cancel := context.WithCancel(context.Background())
    defer cancel()

    errChan := make(chan error, 2)

    // A. Forward aggregated events to Sentinel daemon
    go func() {
        for {
            select {
            case <-ctx.Done():
                return
            case event, ok := <-agg.Events():
                if !ok {
                    errChan <- fmt.Errorf("aggregator events channel closed")
                    return
                }
                b, err := json.Marshal(event)
                if err != nil {
                    log.Printf("[audit-consume] Failed to marshal event: %v", err)
                    continue
                }
                line := fmt.Sprintf("EVENT %s\n", string(b))
                log.Printf("[audit-consume-debug] Sending to socket: %q", line)
                if _, err = fmt.Fprintf(conn, "%s", line); err != nil {
                    errChan <- err
                    return
                }
            }
        }
    }()

    // B. Receive control messages (SET_MAP) from Sentinel daemon
    go func() {
        scanner := bufio.NewScanner(conn)
        for scanner.Scan() {
            line := scanner.Text()
            if strings.HasPrefix(line, "SET_MAP ") {
                var paths []string
                if err := json.Unmarshal([]byte(line[8:]), &paths); err != nil {
                    log.Printf("[audit-consume] Failed to unmarshal SET_MAP: %v", err)
                    continue
                }
                agg.SetWatchPaths(paths)
            }
        }
        if err := scanner.Err(); err != nil {
            errChan <- err
        } else {
            errChan <- fmt.Errorf("sentinel closed connection")
        }
    }()

    // Wait for first error from either goroutine, then cancel both
    err := <-errChan
    log.Printf("[audit-consume] IPC Error: %v. Reconnecting...", err)
    // cancel() is called by defer, which causes goroutine A to exit via ctx.Done()
    // conn.Close() is called by defer, which causes goroutine B's scanner to return EOF
}
```

Also update the call signature in `runAuditConsumer` — no change needed as `handleSentinelConn` still has the same external signature `(conn net.Conn, agg *auditmon.Aggregator)`.

## Task 2 — Fix CR-002: Hold mutex across entire `emitPartial` gate check

**File:** `src/sentinel/internal/auditmon/aggregator.go`

**Problem:** `emitPartial` currently:
1. Acquires `a.mu`, deletes buffer, releases lock (line 308-315)
2. Re-acquires `a.mu` to read `a.canaryMap` (line 324-333)

Between steps 1 and 2, `SetWatchPaths` can change `canaryMap`, causing a stale-read race.

**Fix:** Hold the mutex for the entire operation. Replace `emitPartial` (lines 307-355):

```go
func (a *Aggregator) emitPartial(key string) {
    a.mu.Lock()

    buf, ok := a.buffers[key]
    if !ok {
        a.mu.Unlock()
        return
    }
    delete(a.buffers, key)

    // C-02: Gate partial events on canaryMap (same requirement as isComplete).
    // Must check BEFORE releasing the lock to avoid TOCTOU with SetWatchPaths.
    if len(buf.paths) == 0 {
        a.mu.Unlock()
        return
    }

    var path string
    for _, fields := range buf.pathsFields {
        p := strings.Trim(fields["name"], "\"")
        if a.canaryMap[p] {
            path = p
            break
        }
    }
    a.mu.Unlock()

    if path == "" {
        return
    }

    event := &AuditEvent{
        ID:         buf.id,
        Timestamp:  buf.ts,
        PID:        buf.pid,
        Confidence: ConfIncomplete,
        Path:       path,
    }
    if buf.syscall != nil {
        fields := buf.syscallFields
        fmt.Sscanf(fields["uid"], "%d", &event.UID)
        event.Comm = strings.Trim(fields["comm"], "\"")
        event.Exe = strings.Trim(fields["exe"], "\"")
        var sys int
        fmt.Sscanf(fields["syscall"], "%d", &sys)
        event.Op = identifyOp(sys)
    }
    a.emitChan <- event
}
```

Note: The `a.mu.Unlock()` before the `emitChan` send is intentional — `emitChan` is a buffered channel and sending to it while holding the mutex would cause a deadlock if the channel is full (janitor would also need the lock to proceed). The lock is only needed to protect map reads; releasing before the channel send is correct.

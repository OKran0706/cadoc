# 05-01: Hybrid Credential Persistence

## Objective
Modify the Sentinel credential flow so that after fetching TLS credentials from Vault:
1. `ca.crt` and `mtls.crt` are written as raw PEM to `/var/lib/canary/` (atomic write-then-rename).
2. `mtls.key` is kept strictly in memory — never touches disk.
3. On restart without `--join-token`, Sentinel loads the disk certs and uses Vault's TLS cert auth backend to re-authenticate and obtain fresh credentials.

## Tasks

```xml
<task id="add_persist_and_load_helpers">
  <action>
    In `src/sentinel/internal/sysutil/sysutil.go`, add two new exported functions:

    - Remove the hard rejection of disk-based certificates.

    - Keep the private key (`clientKeyData`) strictly from Vault — never from disk.

       c. On success: fetch fresh secrets (new certs + private key into memory), then persist the new public certs.
       d. On failure (403 or any error): log "Awaiting approval" and enter the polling loop (Phase 6 handles this, for now just log.Fatal).

    3. Add a `--state-dir` flag defaulting to `/var/lib/canary` so the cert path is configurable.
```
